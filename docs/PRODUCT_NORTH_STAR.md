# Schulferienklar Product North Star

> 수익화와 시장 검증의 현재 실행 기준은
> [`MONETIZATION_STRATEGY.md`](./MONETIZATION_STRATEGY.md)를 따른다.

> 이 문서는 Schulferienklar의 제품·기술·데이터·수익화 방향을 판단하는 최상위 기준이다.
>
> 개별 페이지 개선, 디자인 수정, SEO 작업, 다운로드 기능을 진행하더라도
> 프로젝트는 항상 이 문서의 방향으로 돌아온다.

---

## 1. North Star

Schulferienklar의 목표는 단순한 독일 방학 정보 사이트가 되는 것이 아니다.

> **사람에게는 가장 편한 독일 일정 도구가 되고,<br>
> AI와 다른 서비스에는 가장 신뢰할 수 있는 독일 일정 데이터 공급자가 된다.**

독일의 Schulferien, Feiertage, unterrichtsfreie Tage, Brückentage 데이터를
사용자가 읽기만 하는 정보에서 바로 행동할 수 있는 도구로 바꾼다.

---

## 2. 2026년 이후의 전제

검색 엔진과 브라우저는 이미 사용자의 질문에 AI 답변을 먼저 제공하기 시작했다.

단순한 날짜와 일반 설명은 검색 결과 안에서 요약될 수 있다.
따라서 페이지 수나 글의 양만으로는 장기적인 경쟁력이 만들어지지 않는다.

Schulferienklar는 다음 자산을 축적해야 한다.

- 공식 출처에서 확인한 정규화된 데이터
- 출처와 확인일이 포함된 신뢰 구조
- 웹페이지·ICS·PDF·API에서 함께 사용하는 계산 엔진
- 사용자가 직접 계산하거나 입력하지 않아도 되는 행동 기능
- 다른 서비스가 사용할 수 있는 API와 위젯
- 데이터 수정과 변경을 추적할 수 있는 운영 체계

---

## 3. 해결하려는 실제 문제

사람들은 방학 날짜 자체보다 그 날짜를 이용해 무엇을 해야 하는지가 필요하다.

사용자가 직접 해야 하는 일을 줄인다.

- 방학 날짜를 찾아 여러 사이트와 비교하는 일
- 공휴일과 주말을 합쳐 연속 휴일을 계산하는 일
- 휴가를 며칠 사용해야 하는지 계산하는 일
- 날짜를 자신의 캘린더에 하나씩 입력하는 일
- 여러 Bundesland의 일정을 각각 비교하는 일
- 공식 데이터가 바뀌었는지 다시 확인하는 일
- 가족이나 동료에게 일정을 다시 정리해서 전달하는 일

Schulferienklar는 정보를 보여주는 데서 끝나지 않고
이 계산과 입력을 대신해야 한다.

## 4. 핵심 사용자 약속

### 빠르게 이해한다

- 주와 연도를 선택하면 필요한 날짜가 바로 보인다.
- Ferien, Feiertag, unterrichtsfrei를 명확하게 구분한다.
- 과도한 광고와 불필요한 설명으로 사용자를 방해하지 않는다.

### 바로 행동한다

- 캘린더에 추가한다.
- 구독형 캘린더로 자동 업데이트를 받는다.
- PDF 또는 PNG로 저장하고 출력한다.
- 가족이나 동료에게 공유한다.
- 여러 주의 일정을 비교한다.

### 믿을 수 있다

- 공식 출처를 표시한다.
- 마지막 확인일을 표시한다.
- 계산 결과와 공식 데이터를 구분한다.
- 지역 한정 공휴일을 주 전체 공휴일처럼 표현하지 않는다.
- 변경 내역과 데이터 버전을 관리한다.

## 5. 경쟁력의 중심

Schulferienklar의 경쟁력은 화려한 기술을 보이는 데 있지 않다.

기술은 사용자에게 보이지 않게 작동해야 한다.

사용자는 다음만 느껴야 한다.

- 빠르다.
- 정확하다.
- 이해하기 쉽다.
- 다시 입력할 필요가 없다.
- 다른 사이트보다 한 단계 더 해준다.

내부적으로는 다음이 경쟁력이 된다.

1. 공식 데이터 정규화
2. 재사용 가능한 계산 엔진
3. 출처와 변경 이력
4. 16개 Bundesland 확장 구조
5. 웹·캘린더·다운로드·API의 일관성
6. 실제 사용 행동 데이터
7. API와 위젯을 통한 외부 배포

---

## 6. 하나의 데이터 엔진

웹페이지, Jahreskalender, ICS, PDF, PNG, API는
각자 날짜를 따로 관리해서는 안 된다.

모든 출력은 하나의 공통 데이터 엔진에서 생성되어야 한다.

```text
공식 데이터
    ↓
정규화된 내부 데이터
    ↓
검증 및 계산 엔진
    ↓
────────────────────────────
웹페이지
구독형 캘린더
ICS 다운로드
PDF / PNG
JSON API
외부 위젯
────────────────────────────
```

같은 날짜가 출력 방식에 따라 달라지는 구조를 만들지 않는다.

## 8. 제품 개발 순서

### Phase 1 — 신뢰 가능한 검색 진입점

- 주·연도별 핵심 페이지
- 공식 출처와 확인일
- 정확한 메타데이터와 구조화 데이터
- 반복적인 얇은 페이지가 아닌 실용 정보
- Bayern 2027 Gold Page를 첫 기준으로 사용

### Phase 2 — 행동 도구

- Jahreskalender
- ICS 다운로드
- PDF 인쇄
- 직접 다운로드 PDF와 PNG
- Apple Calendar, Google Calendar, Outlook 추가 안내
- 구독형 캘린더 URL

### Phase 3 — 공통 데이터 엔진

- 웹·ICS·PDF가 동일한 데이터와 계산 사용
- 주·연도별 데이터를 같은 스키마로 통합
- 검증 스크립트 강화
- 데이터 변경 이력 관리
- API에 사용할 내부 서비스 계층 준비

### Phase 4 — API v1

초기 후보:

```text
GET /api/v1/states
GET /api/v1/school-holidays?state=BY&year=2027
GET /api/v1/public-holidays?state=BY&year=2027
GET /api/v1/free-periods?state=BY&year=2027
GET /api/v1/bridge-days?state=BY&year=2027
```

API 응답에는 날짜만이 아니라 다음을 포함한다.

- 데이터 유형
- 공식 명칭
- 적용 범위
- 출처
- 확인일
- 데이터 버전
- 계산 방식 버전
- 업데이트 시각

### Phase 5 — AI가 대신하기 어려운 기능

- 여러 Bundesland의 공통 방학 기간
- 두 지역의 일정 비교
- 휴가 일수별 최적 연휴 계산
- 가족 일정 계획
- 학교·회사·여행 일정 조합
- 변경 알림
- 자동 갱신 캘린더
- 사용자의 조건에 맞춘 추천

### Phase 6 — 외부 배포

- 삽입형 캘린더 위젯
- 여행 사이트용 데이터 위젯
- 학교·학원용 위젯
- 회사 인트라넷용 휴일 위젯
- 상업용 API
- 데이터 라이선스

## 10. AI 검색 전략

Schulferienklar는 AI 검색을 속이는 방식으로 성장하지 않는다.

AI가 신뢰하고 인용할 수 있는 원본 자산을 만든다.

- 공식 출처를 가까운 위치에 표시
- 확인일과 데이터 버전 표시
- 질문에 직접 답하는 명확한 문장
- 표와 텍스트를 함께 제공
- 구조화 데이터와 화면 내용을 일치시킴
- 계산 결과의 근거 설명
- 고유한 비교와 계산 결과 제공
- 안정적인 URL 유지
- canonical, sitemap, 내부 링크를 일관되게 관리

AI가 날짜를 요약해도,
사용자는 계산·추가·비교·구독을 위해 Schulferienklar를 사용하게 만든다.

## 11. 기능 결정 체크리스트

새 기능이나 PR을 시작하기 전에 다음을 확인한다.

### 사용자 가치

- 사용자의 계산이나 입력을 줄이는가?
- 사용 시간이 실제로 짧아지는가?
- 모바일에서도 즉시 사용할 수 있는가?

### 데이터 가치

- 재사용 가능한 데이터 자산이 쌓이는가?
- 출처와 확인일을 유지할 수 있는가?
- 웹·ICS·PDF·API에서 함께 사용할 수 있는가?

### 확장성

- Bayern 하나에서 끝나지 않는가?
- 16개 Bundesland로 확장할 수 있는가?
- 다른 연도에도 같은 구조를 사용할 수 있는가?

### AI 및 검색

- AI가 이해하고 인용하기 쉬운가?
- 단순 복제 페이지가 아닌 고유한 가치가 있는가?
- 검색 결과에서 클릭하지 않아도 끝나는 정보만 만드는 것은 아닌가?

### 수익화

- API, 구독, 위젯, 프리미엄 기능으로 연결될 수 있는가?
- 실제 사용 행동을 측정할 수 있는가?
- 무료 사용자와 유료 사용자의 가치를 구분할 수 있는가?

다섯 영역 중 대부분에 기여하지 않는 작업은 우선순위를 낮춘다.

## 12. 하지 않을 것

- 주와 연도만 바꾼 얇은 SEO 페이지 대량 생성
- 공식 데이터와 계산 결과를 섞어 표현
- 실시간 데이터가 없는데 실시간처럼 보이게 표현
- 페이지마다 별도 날짜를 수동 관리
- 유지할 수 없는 기능을 빠르게 늘리는 것
- 기술적으로 화려하지만 사용자의 귀찮음을 줄이지 않는 기능
- 광고를 위해 읽기 어려운 페이지를 만드는 것
- 검증되지 않은 AI 생성 날짜를 공식 데이터처럼 사용
- 검색 순위만을 위한 의미 없는 콘텐츠 생산

## 15. 역할

제품 소유자는 사람들의 불편을 발견하고,
아이디어와 우선순위를 결정한다.

기술 파트너는 그 아이디어를 다음으로 바꾼다.

- 실제 작동하는 기능
- 확장 가능한 데이터 구조
- 검증 가능한 계산
- 안전한 Git과 배포 과정
- AI 시대에 맞는 제품 판단
- 수익화 가능한 기술 기반

기술은 창의성을 제한하는 장벽이 아니라,
아이디어를 빠르게 현실로 만드는 기반이어야 한다.

## 16. 최종 판단 기준

Schulferienklar는 과거의 정보 사이트를 더 예쁘게 만드는 프로젝트가 아니다.

> **독일의 방학과 공휴일을<br>
